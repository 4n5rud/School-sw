## 슬라이드 3 · P1 vs P2 — 개발 관점 비교

| 관점 | P1 | P2 |
|------|----|----|
| **핵심 액터** | 수강생(STUDENT) | 강사(TEACHER) + 수강생 양방향 |
| **핵심 동선** | 탐색 → 수강신청 → 영상 시청 | 강의 업로드·관리 + 리뷰·Q&A + 결제·수료 |
| **파일 스토리지** | videoUrl 하드코딩 | Cloudflare R2 실 파일 업로드 |
| **UI 테마** | 다크 테마 | 라이트 클린 테마 (인프런 스타일) |
| **DB 테이블 수** | 5개 | 9개 (+4 신규) |
| **API 엔드포인트** | ~12개 | ~40개 |

**P1 = 소비 동선 MVP**
**P2 = 생산·소비 양방향 플랫폼 완성**

## 슬라이드 4 · P1에서 완성된 것

수강생(STUDENT) 핵심 동선 완성

```
강의 탐색 → 상세 보기 → 수강신청 → 영상 시청 → 내 강의실
```

- 홈: 키워드 검색, 카테고리 필터, 페이지네이션
- 강의 상세: 커리큘럼 미리보기, 수강신청 버튼
- 학습 플레이어: R2·YouTube 영상 재생, 섹션 사이드바
- 내 강의실: 수강 목록 확인
- 인증: 로그인 / 회원가입 (STUDENT·TEACHER·ADMIN 역할)

## 슬라이드 8 · 핵심 기술 — Cloudflare R2 업로드 파이프라인

**왜 이 방식인가?** → 동영상이 BE 서버를 거치지 않아 서버 부하 없이 대용량 처리 가능

```
① 브라우저 → BE: POST /video-presigned
   { lectureId, filename, contentType, fileSize }

② BE → R2: Pre-signed URL 생성
   ← { uploadUrl, objectKey, expiresAt }

③ 브라우저 → R2: PUT uploadUrl (BE 미경유, 직접 업로드)

④ 브라우저 → BE: POST /video-confirm
   { lectureId, objectKey }

⑤ BE → R2: headObject() 확인 → lecture.videoUrl 저장
```

**트러블슈팅**: `ERR_SSL_VERSION_OR_CIPHER_MISMATCH`
- 원인: AWS SDK 기본 virtual-hosted-style URL이 R2 SSL 인증서와 불일치
- 해결: `pathStyleAccessEnabled(true)` 적용

## 슬라이드 9 · DB 변화 — P1 → P2

**P1 스키마 (5테이블)**
`MEMBER` · `COURSE` · `SECTION` · `LECTURE` · `ENROLLMENT`

**P2 신규 추가 (4테이블)**

| 테이블 | 역할 |
|--------|------|
| `REVIEW` | 강의 리뷰·별점 (member×course Unique) |
| `WISHLIST` | 찜 목록 (member×course Unique) |
| `PAYMENT` | 결제 내역 (더미, 상태 Enum 관리) |
| `COURSE_QUESTION` | 강의 Q&A (강사 답변 인라인 저장) |

**P1 컬럼 확장**

| 테이블 | 추가 컬럼 |
|--------|-----------|
| `MEMBER` | `bio`, `profile_image_url` |
| `COURSE` | `is_published` |
| `LECTURE` | `upload_status` (PENDING·CONFIRMED·FAILED) |
| `LECTURE_PROGRESS` | `is_completed` |
| `VIDEO_UPLOAD` | 신규 테이블 (R2 업로드 메타데이터) |

## 슬라이드 10 · 페이지 구조 변화

**P1 → P2 신규·확장된 페이지**

```
신규 페이지
├── /profile              내 프로필 (닉네임·비밀번호 변경, 탈퇴)
├── /instructor/[id]      강사 프로필 + 강사 강의 목록
├── /wishlist             찜 목록
├── /payment/[courseId]   결제 (더미)
├── /payments             결제 내역
├── /certificate/[courseId] 수료증
└── /teacher/courses/[id]/questions  Q&A 관리

확장된 페이지
├── /courses/[id]         리뷰·Q&A·찜 버튼 추가
└── /learning/[courseId]  진도 체크·완강 배너 추가
```

P1 기준 7개 페이지 → P2 기준 15개 페이지

## 슬라이드 11 · 보안 설계

| 위협 | 대응 |
|------|------|
| Pre-signed URL 악용 | 유효시간 1시간 제한 |
| 허용되지 않은 파일 형식 | Content-Type 화이트리스트 |
| 대용량 파일 공격 | 최대 5GB 제한 (Pre-signed URL 발급 단계) |
| 다른 강사 강의 수정 | `instructorId == currentMemberId` 소유권 검증 → 403 |
| TEACHER 계정 수강신청 | FE·BE 양쪽 역할 차단 |
| 본인 리뷰만 수정·삭제 | `memberId == currentMemberId` 검증 |

## 슬라이드 13 · 정리

**P1 = 수강생이 강의를 탐색하고 시청하는 최소 동선 (MVP)**

**P2 = 강사와 수강생이 모두 활동하는 양방향 플랫폼**

- 강사: 강의 제작부터 수강자 관리까지 완전한 파이프라인
- 수강생: 리뷰·Q&A·찜·결제·수료증으로 경험 완성
- 기술: Cloudflare R2 실 파일 업로드, 전체 UI 리디자인

> "강의를 올리는 사람"과 "강의를 듣는 사람" 모두를 위한 플랫폼 완성
